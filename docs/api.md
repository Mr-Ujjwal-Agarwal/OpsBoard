# API reference

Base URL (local development): `http://localhost:8000/api`

Interactive documentation is auto-generated by FastAPI and always reflects the current code:

- Swagger UI: `http://localhost:8000/docs`
- ReDoc: `http://localhost:8000/redoc`
- Raw OpenAPI schema: `http://localhost:8000/openapi.json`

## Response conventions

All successful responses return JSON. All error responses share a consistent envelope:

```json
{
  "success": false,
  "error": "Task with id 42 was not found.",
  "details": null
}
```

`details` is populated with field-level information on `422` validation errors.

## Health

### `GET /api/health`

General-purpose status check. Always returns `200` if the process is running.

```json
{ "status": "ok", "service": "OpsBoard API", "version": "1.0.0" }
```

### `GET /api/ready`

Checks database connectivity. Returns `200` when ready, `503` when the database is unreachable. Intended to back a Kubernetes `readinessProbe`.

### `GET /api/live`

Confirms the process is alive. Has no external dependencies, so it stays `200` even during a database outage. Intended to back a Kubernetes `livenessProbe`.

## Tasks

### `GET /api/tasks`

List tasks, most recently created first.

| Query param | Type | Description |
|---|---|---|
| `search` | string | Case-insensitive match against title and description |
| `status` | `pending` \| `in_progress` \| `completed` | Filter by status |
| `priority` | `low` \| `medium` \| `high` | Filter by priority |

All parameters are optional and combine with AND semantics.

**Response `200`**
```json
{
  "total": 2,
  "items": [
    {
      "id": 1,
      "title": "Write deployment documentation",
      "description": "Document the docker compose workflow.",
      "status": "in_progress",
      "priority": "high",
      "created_at": "2026-07-01T12:00:00Z",
      "updated_at": "2026-07-01T12:00:00Z"
    }
  ]
}
```

### `GET /api/tasks/statistics`

Aggregate counts used to populate the dashboard's stat cards.

**Response `200`**
```json
{
  "total": 6,
  "pending": 3,
  "in_progress": 1,
  "completed": 2,
  "low_priority": 1,
  "medium_priority": 3,
  "high_priority": 2,
  "completion_rate": 33.33
}
```

### `GET /api/tasks/{task_id}`

Fetch a single task. Returns `404` if it doesn't exist.

### `POST /api/tasks`

Create a task.

**Request body**
```json
{
  "title": "Configure Prometheus scrape targets",
  "description": "Optional",
  "status": "pending",
  "priority": "medium"
}
```

`title` is required (1–200 characters). `status` defaults to `pending`, `priority` defaults to `medium` if omitted. Returns `201` with the created task, or `422` on validation failure.

### `PATCH /api/tasks/{task_id}`

Partially update a task — only send the fields you want to change.

**Request body (any subset)**
```json
{ "status": "completed" }
```

Returns `200` with the updated task, or `404` if the task doesn't exist.

### `POST /api/tasks/{task_id}/complete`

Convenience endpoint that sets a task's status to `completed` without needing to construct a PATCH body. Returns `200` with the updated task.

### `DELETE /api/tasks/{task_id}`

Delete a task. Returns `200`:

```json
{ "success": true, "message": "Task 1 deleted successfully." }
```

## Status codes summary

| Code | Meaning |
|---|---|
| `200` | Success |
| `201` | Resource created |
| `404` | Resource not found |
| `422` | Request validation failed |
| `503` | Service not ready (readiness check only) |
| `500` | Unexpected server error |
