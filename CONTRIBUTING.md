# Contributing to OpsBoard

Thank you for your interest in contributing to **OpsBoard**.

Whether you are fixing bugs, improving documentation, enhancing infrastructure, or proposing new features, your contributions are appreciated.

---

# 📖 Getting Started

Before contributing, please:

- Read the project documentation
- Understand the project architecture
- Follow the existing coding and documentation style
- Test changes locally before submitting

---

# 🌿 Branch Strategy

Please create a separate branch for every change.

Example:

```text
feature/add-monitoring-dashboard

bugfix/fix-api-routing

docs/update-readme
```

Avoid making changes directly to the `main` branch.

---

# 💬 Commit Message Guidelines

Use clear and descriptive commit messages.

Examples:

```text
feat: add Helm deployment configuration

fix: resolve Kubernetes service selector

docs: update deployment documentation

refactor: improve Terraform module structure
```

---

# 🚀 Pull Request Process

1. Fork the repository.
2. Create a new branch.
3. Make your changes.
4. Test the changes locally.
5. Commit your changes.
6. Push the branch.
7. Open a Pull Request.

---

# ✅ Pull Request Checklist

Before submitting a Pull Request, ensure that:

- [ ] Code builds successfully
- [ ] Documentation is updated if required
- [ ] No sensitive information is included
- [ ] Existing functionality remains unaffected
- [ ] Changes have been tested locally

---

# 🐞 Reporting Issues

If you discover a bug, please use the provided GitHub Bug Report template.

Include:

- Steps to reproduce
- Expected behavior
- Actual behavior
- Environment details
- Relevant logs or screenshots

---

# ✨ Suggesting Features

Feature requests are welcome.

When proposing a feature, please include:

- Problem statement
- Proposed solution
- Expected benefits
- Additional context if applicable

---

# 📚 Documentation Contributions

Documentation improvements are encouraged.

Examples include:

- Fixing errors
- Improving clarity
- Updating examples
- Expanding technical explanations

---

# 🤝 Code of Conduct

Please maintain a respectful and collaborative environment.

Constructive feedback and professional communication help improve the project for everyone.

---

# 📌 Questions

If you have questions about the project, architecture, or implementation, feel free to open an issue for discussion before starting major changes.

---

# ❤️ Thank You

Thank you for taking the time to contribute to OpsBoard.

Every contribution, whether it is code, documentation, testing, or feedback, helps improve the project and makes it more valuable for the community.
